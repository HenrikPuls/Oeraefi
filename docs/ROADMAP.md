# Implementation Roadmap

Working doc that orders implementation into milestones. Each milestone is sized for one agentic session: **plan-mode refine → implement → verify (local test gate) → user approval → commit(s)**. Game-design rationale lives in `docs/concept/` (German); this roadmap only sequences the work.

**Working mode (the user writes no code):** everything is LLM-generated. The user approves diffs/commits, playtests in the Unity Editor, and decides open design questions via structured questions before the affected milestone starts.

**Asset-generation rule:** scenes, prefabs, and ScriptableObject assets are only ever created via editor scripts (batchmode `-executeMethod`) — never by hand-editing `.unity`/`.prefab` YAML. `.meta` files are generated by Unity import and committed with their assets.

## M5 — Playable Slice (rebuilt)

Runtime bootstrap (`RuntimeInitializeOnLoadMethod`), isometric camera rig, calendar ticker, sandbox HUD. Scene is generated by an editor script (old scenes are not migrated). Introduce PlayMode smoke tests beyond M0's.

**User smoke check:** press Play → date/season advances, farm produces, workers can be assigned roles.

## M6 — Buildings & Construction

`BuildingSystem`/`BuildingManager`/placement (Phase-C state of the old project), regenerate the 7 building-plan SOs via generator. **Design pre-step:** building cost table does not exist in the concept doc — draft a table for user approval first (game-design decision).

## M7 — Save/Load

Clean up the old `SaveSystem`; **ADR-006 save format** (versioned JSON, migration policy). From here on, every persisted-structure change is flagged before implementation (CLAUDE.md rule).

## M8 — Visual Pass: CC0 Asset Packs

Fetch CC0 low-poly packs (Kenney / Quaternius) via `tools/assets/` scripts so the LLM can integrate them autonomously; replace procedural placeholder props; model-import postprocessors. **ADR-007 asset sourcing & binary/LFS policy.**

## M9 — Geothermal

Two source types (low-temp fields vs. high-temp volcanic zones, concept doc 6): heating, cooking, craft uses, heated beds, sulfur export. Settlement-site choice becomes strategically differentiated.

## M10 — Seasonal Norway Trade

Sailing window May–September; harbor handover (safe, low margin) vs. own helmsmanship + ship shares (higher margin, storm risk) (concept doc 4.2–4.4).

## M11 — Dynasty

Marriage (profile mixing), children with partially inherited skills, inheritance/heirs, age-dependent performance curves, emergent mortality. **Decision:** explicit no-win sandbox statement (**ADR**).

## M12 — Weather

**Design pre-step:** weather model scope (event-probability model recommended over simulated fronts). Couplings: hay harvest risk, sailing window, fowling season, cold→vitality.

## M13 — Two-Tier NPC World

Neighboring farm agents at reduced tick rate (concept doc 4.1), local market aggregation, minimal world overview UI.

## M14 — Combat (thin) + Polish

Combat as risk, not progression: 2d10 contest resolution, farm defense, þing arbitration as alternative path. Final UI pass. Sound is explicitly optional/post-roadmap (concept doc 12.2).

---

**Milestones after M5 are provisional** — the real quality of the migrated predecessor code is assessed during M2–M5, and the plan is adjusted accordingly.

**Standing rules for every milestone:**
- Save-format-relevant changes are flagged and confirmed before implementation
- Balancing values are only ever changed by the user in the Inspector (game-design decisions)
- Every milestone ships with tests, arc42 updates where architecturally relevant, `docs/status/CURRENT.md` update, and approval-gated conventional commits
- Concept gaps blocking a milestone are resolved with the user *before* implementing that milestone
